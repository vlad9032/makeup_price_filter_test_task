# Тестове завдання: QAAutomation (Playwright + TypeScript)

## 1. Запуск

- Node.js 20 або новіший (мінімум для Playwright 1.65), у мене 24
- `git clone https://github.com/vlad9032/makeup_price_filter_test_task.git`
- `npm ci`
- `npx playwright install chromium`
- `npx playwright test` — усі тести, desktop і mobile
- `npx playwright test --project=desktop` / `--project=mobile`
- `npx playwright test -g "only from"` — один тест за назвою
- `npx playwright test --headed` — з видимим браузером
- `npx playwright show-report` — HTML-звіт
- потрібен інтернет, тести ходять на живий сайт
- також можна запускати через інтерфейс VScode

Тести only to і preset "X - Y" можуть падати через BUG-1 (див. розділ 4) — це очікувано, тест знайшов баг

## 2. Що покрито

Обрав категорію «Чоловіча парфумерія», `/ua/categorys/3218/`
Кожен тест проходить на двох проектах (chrome i mobile (s24))

Тести

1. from and to — «Від» + «До», перевіряємо усі ціни на сторінці в діапазоні
2. only from — тільки «Від», усі ціни ≥ від
3. only to — тільки «До», усі ціни ≤ до
4. preset «Менше X» — тільки верхня межа
5. preset «X - Y» — обидві межі (береться готовий діапазон, у який потрапляє медіана цін)
6. preset «Більше X» — тільки нижня межа
7. скидання через плашку — окремий тест
 


## 3. Що знайшов після ручної перевірки

- фільтр на сайті називається «Вартість», а не «Ціна»
- є готові діапазони: "Менше 50 ₴", "1000 ₴ - 5000 ₴", "Більше 5000 ₴"
- при фільтрі змінюються ціни й адреса: `#price_from=100&price_to=500`
- значення застосовується, коли клікаєш на пусте місце; Enter і Esc не працюють
- клік на плашку над списком скидає фільтр
- на телефоні не дуже зручно фільтр застосовувати, якщо провести по списку брендів вони починають прокручуватися замість того щоб пролистати фільтр униз, бренди не можна сховати як інші параметри товара
- після введення в перше поле в друге вводиться не одразу: сайт перезавантажує список, і введення в цей час губиться

- величезне число (багато 9'ок) в полі перетворюється на `1.0000000000000003e+21`
- у поле "до" можна ввести менше ніж у поле "від", ніяк не блокується
- сервер надсилає сторінку з `<html lang="en">`, JS міняє на `uk` приблизно через секунду. Тому Chrome пропонує переклад. У DevTools Elements видно `uk` (жива сторінка), у Ctrl+U після перезагрузки сторінки видно `en` (те, що надіслав сервер) - це я просто хотів плашку з перекладом відключити
- у полів "Від" і "До" немає доступного імені: порожній `<label>`, немає placeholder і name. Скринрідер прочитає просто "поле введення". Тому запис (codegen) дав тільки `getByLabel('').first()` (але про це мені Клод сказав)
- рекламні товари ("Sponsored") відключив у тестах, не маю вимог, а такі товари в теорії можуть бути поза фільтром
- скелетон (сірі заглушки) знайшов через DevTools → Network → 3G. Використав їх щоб розділити старі картки від нових (відфильтрованих)

## 4. Баг ціни (BUG-1)

- Для деяких товарів ціна на картці не збігається з ціною, за якою працює фільтр
- тому у видачі бувають картки поза діапазоном, а фільтр «від X до X» з ціною з картки товар не знаходить
- стосується окремих товарів: максимум один такий на сторінці видачі, ловив через раз
- баг залежить від даних, думаю причина у зміні цін і якихось акціях
- точна причина невідома, тому один баг із кількома прикладами
- майже усі приклади я повторив вручну, скриншоти в `findings/`
- подробиці у BUGS.md

## 5. Мої рішення

- Завдання було перевіряти через UI, тому кожен тест ставить ціну, а не переходить за посиланням з готовим фільтром
- перевіряю тільки першу сторінку видачі. На реальному проєкті одразу сортував би за ціною і перевіряв першу й останню сторінку: перша картка — мінімум усієї видачі, остання — максимум
- у кожному тесті спочатку перевірка, що товари є (порожній список пройшов би «усі ціни в діапазоні»)
- діапазон беру з цін першої сторінки при кожному запуску, беру середину диапазону, відсікая 25% по краях
- передумови: щонайменше 4 товари і "Від" < "До". Інакше тест одразу падає зі зрозумілим повідомленням. Це на випадок якщо в нас всього 2 товари
- межі включні: у прогоні мін/макс після фільтра точно збіглися з межами
- готові діапазони читаю зі сторінки, а не хардкоджу: тест не зламається, якщо магазин змінить діапазони
- готові діапазони розбив на 3 класи еквівалентності за видом межі, по одному тесту на клас
- реклама виключена з перевірки (вимоги до реклами незрозумілі)
- тест суворий: перевіряє ціну на картці, як бачить покупець. Під баг не підганяв. Поки у видачі товар із багом, тест фейл
- баг залишив у BUGS.md, у інший день на інших даних тест може пройти
- скидання через плашку — окремий тест. Спочатку AI поставив перевірку скидання в усі три тести з готовими діапазонами. Я вирішив перевіряти один раз: плашка однакова, її поломка має фейлити один тест, а не три. Потім поставив останнім кроком у тест preset «X - Y», але помітив, що він падає раніше на багу ціни, і скидання не перевірятиметься, поки баг не виправлять. Тому виніс в окремий тест, який не перевіряє ціни
- тести на степи ділив тільки в тестах із готовими діапазонами та скиданням, де кілька етапів: видно, на якому етапі впало, а назва кроку показує, яку саме кнопку діапазону натиснуто (вона читається зі сторінки)
- копійки не підтримую: вимог немає, на makeup ціни цілі (на Rozetka теж без копійок; на Prom ціні з копійками). Якщо знадобиться — перепишу parsePrice, який залишає цифри й кому, міняє кому на крапку і падає зі зрозумілою помилкою
- одна категорія. щоб масштабувати можна добавити вібір рандомної категорії, ввід конкретної категорії перед початком тесту, або перевірку всіх категорій (наприклад для нічного прогону, бо це займе час)
- у помилці видно назву ціну і назву товара, щоб легко дебажити
